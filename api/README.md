<h1 align="center">Look News — API</h1><p align="center">  Backend em Go que busca feeds RSS/Atom/RDF, filtra por relevância com IA e serve tudo pronto via HTTP.</p>[⬅ Voltar para a documentação principal](../README.md)## Sumário- [Rodando localmente](#rodando-localmente)- [Como chamar a API](#como-chamar-a-api)- [Referência](#referência)- [Exemplos](#exemplos)- [Ambientes](#ambientes)## Rodando localmenteVocê vai precisar de [Go](https://go.dev/dl/) e [`make`](https://www.gnu.org/software/make/) instalados, e uma [chave de API da Groq](https://console.groq.com/keys) (usada no filtro de relevância por IA).> `make` no macOS já vem com as Command Line Tools do Xcode. No Windows, use via WSL ou Git Bash.```bashmake download```Crie um `.env` nesta pasta:```bashGROQ_API_KEY=sua-chave-aqui```Suba o servidor:```bashmake run```A API sobe em `http://localhost:8080`.## Como chamar a APIA API tem uma rota principal: `GET /news`. Você manda um **critério de relevância** (texto livre, ex: "tecnologia e startups") e uma ou mais **URLs de feed** — a API busca cada fonte, filtra os artigos relevantes usando IA e devolve tudo pronto em JSON.**📘 Quer explorar sem escrever código?** A API gera documentação interativa (Swagger) automaticamente — dá pra ver todas as rotas e testar chamadas direto pelo navegador:| Ambiente | Swagger UI ||---|---|| Local | [`http://localhost:8080/swagger`](http://localhost:8080/swagger) || Produção | [`https://look-news-api.onrender.com/swagger`](https://look-news-api.onrender.com/swagger) |## Referência### `GET /news`| Query param | Tipo | Obrigatório ||---|---|---|| `criterion` | string — critério de relevância pro filtro | sim || `sources` | array de strings — uma ou mais URLs de feed (`?sources=A&sources=B`) | sim |**`200 OK`**```json{  "articles": [    {      "title": "string",      "summary": "string",      "link": "string",      "date": "2026-08-20T12:00:00Z",      "source": "string",      "author": "string",      "published": "string",      "terms": ["string"]    }  ],  "total": 0}```| Status | Motivo ||---|---|| `304 Not Modified` | `ETag` enviado em `If-None-Match` bate com o atual — sem corpo || `400 Bad Request` | `sources` não foi enviado || `429 Too Many Requests` | limite de 5 req/s por IP excedido (rajada de 15) || `503 Service Unavailable` | todas as fontes falharam e não há cache disponível |A API suporta cache HTTP padrão via `ETag` + `Cache-Control: max-age=60, stale-while-revalidate=300` — uma requisição condicional com `If-None-Match` evita baixar a resposta inteira quando nada mudou.## Exemplos**Uma única fonte:**```bashcurl "http://localhost:8080/news?criterion=tecnologia&sources=https://exemplo.com/feed.xml"```**Múltiplas fontes de uma vez:**```bashcurl "http://localhost:8080/news?criterion=ciência+e+tecnologia&sources=https://exemplo.com/feed.xml&sources=https://outroexemplo.com/rss"```**Requisição condicional (revalida sem baixar tudo de novo):**```bash# primeira chamada — guarda o ETag da respostacurl -i "http://localhost:8080/news?criterion=tecnologia&sources=https://exemplo.com/feed.xml"# -> ETag: "a1b2c3..."# chamada seguinte — usa o ETag guardadocurl -i "http://localhost:8080/news?criterion=tecnologia&sources=https://exemplo.com/feed.xml" \  -H 'If-None-Match: "a1b2c3..."'# -> 304 Not Modified, sem corpo, se nada mudou```**Requisição inválida (sem fontes):**```bashcurl -i "http://localhost:8080/news?criterion=tecnologia"# -> 400 Bad Request```## Ambientes| Ambiente | URL ||---|---|| Local |
